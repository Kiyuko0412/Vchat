# Discord AI 語音機器人

這是我在研究AI時開發的機器人。

之前我做過 Discord 音樂機器人，雖然後續因為官方封殺音樂機器人而報廢，但在過程中學了一些 `ffmpeg` 音訊處理與 Discord 語音方面的一些基礎知識。後來接觸了一些AI，覺得人為打字有些麻煩，在想：**能不能讓AI直接進到語音頻道，讓我能躺著不看手機，也能直接和我用講話的方式聊天?**

---

## 核心

設計了一套三段的處理流程，成功把多個 API 整合在一起。

### 1. 語音轉文字 STT 
* 利用之前開發音樂機器人學到的 `ffmpeg` 進行處理，處理後透過 API 送到免費的 **Groq Whisper-large-v3** 轉成文字。
* 自動判斷錄到的文字是不是雜訊，避免把鍵盤聲等等也丟給 AI 處理。

### 2. 模型 LLM
用Hugging Face上的免費模型 **GLM-4** 來產生回應。
* 設計一個高中生角色，用台灣中文的日常口吻，盡量讓字數控制在 20 字內，讓對話比較自然。
* 自動紀錄 20 則上下文，解決 LLM 沒有記憶的問題，能接續聊過的話題。

### 3. 文字轉語音 TTS
用Edge-TTS來將LLM輸出的文字轉為語音。
* 微調+20%語速與，讓他講話聽起來更符合人設。

---

## Discord API

遇到的最大難點在於如何控制 Discord 的語音狀態。
### 1. 錄音控制
用過去開發音樂機器人時對 `ffmpeg` 的理解，結合AI的協助繼承並改寫了 `discord.sinks.WaveSink` 類別來做到錄音控制：
* 每 0.5 秒檢查一次。如果連續 1.5 秒沒有新的聲音，就判定講完了，停止錄音並交由後續LLM回應。
* 當 AI 正在說話時，如果偵測到野別人說話，會先停止，優先聽人類說話。

### 2. 資源管理
* 確保同一個人的語音處理和播放完後，才會開始下一次錄音，不會音檔衝突。
* 利用 Python 的 `tempfile` 處理錄音暫存檔，播放完就刪除。

### 3. 其他功能
當房間內只剩機器人時，會等 5 秒後自動斷線。
